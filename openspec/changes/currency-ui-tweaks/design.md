# Design

## Context

- Справочник валют — глобальный `currencyDirectory` в `site/app.js`.
  `loadCurrencies()` грузит его через `fetchReport('currencies')` один раз при
  входе в «Отчёты». Ошибка молча игнорируется, кэш `reportsCache`
  сбрасывается только «Обновить» и новым входом. Справочник используют
  пикер эквивалента «Отчётов», пикер «Настроек» и пикеры формы «Добавить
  пару».
- `loadCurrencies()` при отсутствии сохранённой валюты у леджера берёт
  `isoList[0]` из всего справочника.
- Экран «Курсы валют» (`renderCurList`) перерисовывает `#cur-root`
  целиком, строки пар — отдельно (`renderCurRows`), чтобы не терять фокус
  поиска. Записи пар идут через `apiJson`. Ошибка `apiJson` несёт `status` и
  `body`, то есть `error` и `field` из 409 доступны.
- Иконки леджера уже читаются `fetchReport('icons')` (`common`/`user` с
  `icon_type`). Флаги — `icon_type = 1`, как `Icon.IconType.FLAG` на телефоне.
- Режим «Посмотреть как клиент» добавляет `as_user_id` только к
  `/api/reports/*`. REST wallet-api пишет в леджер вошедшего, а не
  просматриваемого.

## Goals / Non-Goals

**Goals:** см. specs (`reports-shell`, `user-settings`, `currency-pairs`).

**Non-Goals:**
- Правка общих валют не делается: wallet-api отвечает `404`, а веб кнопок
  для них не показывает.
- Удаление пары не меняется: оно уже реализовано и описано в
  `currency-pairs`.
- Фильтр по флагу в пикерах формы «Добавить пару» не делается: пара может
  быть нужна и для скрытой валюты (например, курс BTC/USD при эквиваленте
  в USD).
- Загрузка новой картинки иконки из формы валюты не делается: выбираются
  существующие иконки-флаги, как на телефоне.

## Decisions

### D1. Одна функция «валюты для пикера эквивалента»
`eqPickerCurrencies(currentIso)` возвращает элементы `currencyDirectory` с
`show_in_equivalent !== false`, добавляет текущую, если её отсеяли, а при
пустом результате возвращает весь справочник. Её используют
`renderCurrencyPickerList`, `renderSettingsCurrencyPickerList` и автовыбор
в `loadCurrencies` (первая из `eqPickerCurrencies(null)`). Правило из spec
живёт в одном месте, а не в трёх копиях.

### D2. Таблица и форма валют — состояние экрана «Курсы валют»
Состояние хранится рядом с `curAddFormOpen`: `curCurrenciesOpen`,
`curCurrencyForm` (`null` или `{uuid|null, поля}`) и
`curCurrencyIconPickerOpen`. Разметка — `curCurrenciesHtml()` внутри
`renderCurList()`, события — в `wireCurEvents` (тот же делегирующий
слушатель). Таблица использует классы `users`/`users-table-wrap`, иконки —
`categoryIconHtml`, как в `currencyRowHtml`. Пикер иконки — сетка флагов из
`fetchReport('icons')`. Она запрашивается при первом открытии формы и
кэшируется тем же кэшем отчётов.
Альтернатива — отдельная вкладка «Валюты» в таббаре. Её отвергли: это
лишнее место в мобильном таббаре, а запрос был на кнопку.

### D3. Запись через REST wallet-api, затем перезапрос справочника
`POST`/`PATCH`/`DELETE /api/currencies*` идут через `apiJson`, как записи
пар. После успеха из `reportsCache` удаляется ключ справочника валют,
вызывается `loadCurrencies()`, затем перерисовываются таблица и оба
пикера. Ответ `POST`/`PATCH` содержит готовую строку, и её можно было бы
подставить без запроса. Перезапрос выбран, потому что он заодно подтягивает
правки с телефона и не дублирует правило «своя перекрывает общую».
Альтернатива — запись через `/sync/push`. Её отвергли (wallet-api design
D4).

### D4. Тексты 409 — словарь по `error`/`field`
Маленькая функция `currencyErrorText(err)` переводит `err.body.error`
(`duplicate` + `field`, `currency_in_pair`, `currency_in_use`) в тексты из
spec. Тексты совпадают с ошибками формы валюты на телефоне. Иначе
возвращается `err.message`.

### D5. В режиме «Посмотреть как клиент» запись скрыта
Если `viewAsUser` задан, кнопки «Добавить валюту», «Изменить» и «Удалить»
не рендерятся. Иначе администратор, видя валюты клиента, правил бы свой
леджер. Баннер режима уже говорит «только чтение». Пары в этом режиме
имеют ту же проблему, но здесь она не исправляется: это отдельная задача.

### D6. Отсутствующие поля = поведение до правки
`show_in_equivalent === undefined` считается `true`. Если `is_own ===
undefined`, валюта считается общей, и кнопок записи нет. Веб можно выкатить
раньше wallet-report, и он ничего не сломает и не даст писать вслепую.

## Правки в других сервисах

- **wallet-api** (`wallet-api: currency-ui-tweaks`): REST `/api/currencies*`
  (создание, правка, удаление своей валюты, коды `409`), колонка и синк
  флага.
- **wallet-report** (`wallet-report: currency-ui-tweaks`): поля
  `show_in_equivalent`, `is_own`, `icon_uuid`, `precision` в `GET
  /api/reports/currencies`.
- **google-auth, wallet-ai, wallet-gateway**: без правок (gateway уже
  проксирует `/api/*` в wallet-api).

## Risks / Trade-offs

- [Пользователь скрыл текущую валюту, а она всё ещё в пикере] → по spec это
  так задумано: отчёты не перескакивают молча в другую валюту.
- [Валюту правят одновременно веб и офлайн-телефон] → побеждает последняя
  запись (`seq`), как у пар. Веб видит правки телефона при следующем
  перезапросе справочника.
- [Перезапрос справочника после записи сбрасывает открытые пикеры] →
  пикеры перерисовываются закрытыми. Форма к этому моменту уже закрыта.
