# Design

## Context

Секция «Устройства» на «Настройках» рисуется в `#settings-devices`:
`loadSettingsDevices` → `renderSettingsDevicesTable` → `deviceRowHtml`.
Отзыв делают `wireRevokeOneDevice` и `wireRevokeOthers`, они используют
`window.confirm` и `alert`. Все вызовы идут через `apiFetch`, который один раз
тихо делает `/auth/refresh` на `401`. Близкий образец UI — подключение
Telegram (`renderTelegramLinkBox`): одноразовая ссылка рисуется блоком под
кнопкой, без модального окна. Копирование в буфер уже есть в «Доступе»
(`copyAccessLink`). При отсутствии Clipboard API оно делает вид, что
скопировало. Даты форматирует `formatDate(iso)`: она берёт первые 10 символов
ISO-строки и применяет формат из «Формата даты». Зачем это нужно — proposal.md;
требования — `specs/user-settings`.

## Goals / Non-Goals

**Goals:**
- Пользователь выпускает MCP-токен, один раз его видит и копирует вместе с
  готовым конфигом, а дальше видит и отзывает его в общем списке устройств.
- Токен не задерживается в браузере дольше, чем открыт блок показа.

**Non-Goals:**
- Переименование и продление токена. Продление — это выпуск нового:
  потолок в 90 дней намеренный (google-auth `add-mcp-personal-tokens`).
- Отдельный экран или вкладка «MCP». Токен — сессия устройства, поэтому
  место ему в «Устройствах».
- Инструкции для конкретных клиентов, кроме одного конфига (LM Studio).

## Decisions

**1. Блок под кнопкой, а не модальное окно.** Форма и блок показа рисуются в
новом `<div id="mcp-token-box">` в начале `#settings-devices`, по образцу
`telegram-link-box`. Состояние (`null` / `'form'` / `{token, name,
expiresAt}`) живёт в переменной замыкания IIFE, как `telegramLink`.
`renderSettingsDevicesTable` перерисовывает таблицу, а не бокс: таблица
рисуется в отдельный дочерний контейнер. Поэтому перечитывание списка не
стирает показанный токен.
*Альтернатива:* модальное окно. Отвергнута: на сайте нет модалок, кроме
`confirm`/`alert`, и на ширине телефона блок в потоке проще.

**2. Токен исчезает при «Готово» и при уходе с экрана.** «Готово» обнуляет
переменную состояния и очищает бокс. Ушедший с «Настроек» пользователь
теряет блок, потому что `renderSettings` при следующем входе рисует его
пустым, а переменная обнуляется в начале `renderSettings`. Токен выводится в
`<textarea readonly>` через `escapeHtml`. В `localStorage`, `sessionStorage`,
`history.pushState` и `console.*` он не попадает. На ревью это проверяется
поиском по `wmcp_` и по имени переменной.
*Альтернатива:* держать токен до явного «Готово» даже после ухода с экрана.
Отвергнута: проще и безопаснее «один раз — значит, один раз», а выпустить
новый недолго.

**3. Копирование с честным фолбэком.** Новая функция `copyFieldText(field,
btn)`: если есть `navigator.clipboard.writeText`, она пишет текст и на
1,5 с показывает «Скопировано». Если API нет или запись отклонена, функция
вызывает `field.focus(); field.select()` и показывает подсказку «Выделено —
нажмите Ctrl+C (⌘C на Mac)». `copyAccessLink` не трогаем: там ссылка видна
рядом целиком, а здесь секрет, и молчаливый «успех» привёл бы к тому, что
пользователь закроет блок с пустым буфером. Стенд — LAN по `http`, так что
фолбэк будет основным путём, а не редким.
*Альтернатива:* `document.execCommand('copy')`. Отвергнута: API устарел, и
поведение между браузерами разное.

**4. Конфиг — формат `mcp.json` LM Studio.**
```json
{
  "mcpServers": {
    "wallet": {
      "url": "http://<хост>:8090/api/mcp/",
      "headers": { "Authorization": "Bearer wmcp_…" }
    }
  }
}
```
Адрес — `location.origin + '/api/mcp/'`, поэтому test-контур подставит свой
порт. Конфиг строится `JSON.stringify(obj, null, 2)` и выводится во втором
`<textarea readonly>`. **Сверено с документацией LM Studio** (2026-11-02,
<https://lmstudio.ai/docs/app/mcp>, раздел «Install new servers: `mcp.json`»,
пример «Hugging Face MCP Server»): ключ `mcpServers`, у удалённого сервера —
`url` и `headers` с `Authorization: Bearer …`. Формат совпал, правок нет.
Если он поменяется, меняется только `mcpConfigText`, а сценарий «Конфиг
MCP-клиента» не затрагивается: адрес и заголовок те же.

**5. Даты в местном поясе.** `formatDate` отрезает дату от ISO-строки, и для
`2026-10-31T22:30:00Z` в UTC+3 получилось бы «31.10» вместо «01.11». Новый
помощник `formatLocalDateTime(iso, withTime)` строит через `Date` местную
`YYYY-MM-DD` (и `ЧЧ:ММ`) и отдаёт дату в `formatDate`. Это используется для
«Использовался», «Действует до» и даты в блоке показа.

**6. Подписи и подтверждения по платформе.** `deviceRowHtml` показывает
«MCP-клиент» для `platform === 'mcp'` и кладёт `data-platform` и
`data-name` на кнопку «Отозвать». По ним `wireRevokeOneDevice` выбирает
текст подтверждения для MCP. «5 минут» в тексте — срок кеша JWT в wallet-mcp
(`exp` = 300 с при обмене в google-auth).

## Risks / Trade-offs

- [Формат `mcp.json` LM Studio отличается от ожидаемого] → решение 4: правка
  одной функции и README, сверка — первая задача группы.
- [google-auth отдаёт `expires_at` как потолок 90 дней, а не скользящий срок]
  → текст блока верен в обоих случаях: дата — верхняя граница, а про 30 дней
  без использования сказано отдельно.
- [Токен виден на экране — за плечом, на скриншоте] → показ один раз, «Готово»
  стирает. Предупреждение в тексте блока.
- [Ширина телефона: два `textarea` с длинной строкой] → `width: 100%`,
  `word-break: break-all` для токена, проверка на ~375 px.

## Migration Plan

1. Выкатывать после google-auth с `add-mcp-personal-tokens`. Без новых полей
   `/auth/devices` веб работает как раньше: строк «Использовался»/«Действует
   до» нет. Без `/auth/mcp-tokens` выпуск показывает «Не удалось выпустить
   токен: HTTP 404».
2. Откат — предыдущий образ веба. Выпущенные токены продолжают работать и
   видны как сессии с платформой `mcp` (до отката подписи «MCP-клиент» не
   будет, будет `mcp`).
