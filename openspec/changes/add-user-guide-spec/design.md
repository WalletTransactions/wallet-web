# Design

## Context

Справка по системе (`wallet-docs`) ищет по чанкам OpenSpec: `## Purpose` — отдельный
чанк, каждое `### Requirement:` со всеми сценариями — отдельный. Область по токену
у пользователя веба — `wallet-web` и `wallet-web-eqdefault`, вид `spec`; у бота
Telegram и MCP она шире, у Android — только `android-wallet`. Существующие спеки веба
(`manual-operation-entry`, `ai-expense-entry`, …) написаны для разработчика: в них
эндпоинты, идентификаторы, идемпотентность. Поэтому на вопрос «Как добавить трату»
поиск поднимает техническую `ai-expense-entry`, а ответ пересказывает `POST`.
См. proposal.md — мотивация.

Сверка с текущим поведением: `manual-operation-entry` не создаёт переводы,
переводы в вебе только отображаются (`operations-list`); создаются они в
`android-wallet` (`operation-entry`, чип «Перевод»). Названия кнопок и экранов в
сценариях взяты дословно из спек `manual-operation-entry`, `ai-expense-entry`,
`ai-statement-import`, `ledger-access`, `reports-shell`, `reports-overview`,
`spending-analytics`, `wallet-balances`, `user-settings`, `ai-chat` и сверены с
живым вебом test-контура.

## Goals / Non-Goals

**Goals:**
- Один вопрос пользователя — один чанк: заголовок требования повторяет, как люди
  спрашивают, текст — шаги по названиям с экрана.
- Ответ на «Как добавить трату в приложении?» и «Как перевести деньги с карты в
  наличные?» — на языке пользователя и по существу.

**Non-Goals:**
- Менять `wallet-docs`: ни виды, ни область, ни ранжирование. Если ответы не
  улучшатся, это отдельный change в `wallet-docs`.
- Описывать пользовательские сценарии для `android-wallet`: область Android не
  видит `wallet-web`. Отдельный follow-up — такая же спека в `android-wallet`.
- Дублировать поведение экранов: сценарии ссылаются на названия, а правила проверок и
  ошибок остаются в спеках экранов.

## Decisions

**Новая спека `user-guide` в wallet-web, а не правка существующих.** Спека — один
файл с чанками «вопрос → шаги»; технические спеки остаются точными и неизменными.
Альтернатива — переписать `manual-operation-entry` и другие простым языком:
отвергнута, потому что нормативный текст для разработчика и текст для
пользователя ломают друг друга и перегружают чанк.

**Формат требования — вопрос в заголовке, шаги в тексте, примеры формулировок в
сценариях.** Полнотекстовый поиск и эмбеддинги работают по заголовку и тексту
чанка, а сценарии с живыми формулировками («Как внести расход?», «Как
записать зарплату?») подтягивают чанк при вопросах другими словами.

**Правда о возможностях важнее полноты.** Перевод в вебе создать нельзя — спека так
и говорит и отправляет в Android. Альтернатива — промолчать о переводах:
отвергнута, потому что вопрос «как перевести» — один из первых у пользователя, и отказ
(«В описании системы этого нет») выглядит как поломка.

**Требование «Ответы без внутренних терминов» проверяется вопросом, а не кодом.**
Сервис ответа не меняется; требование задаёт приёмку живым запросом к «Справке» и
защищает от ухудшения при будущих правках текста.

**Другие сервисы:** правок `wallet-docs`, `wallet-gateway`, `wallet-ai`,
`google-auth` не требуется. Индекс заливает job `docs-index` (ночью, только test)
скриптом `wallet-infra/infra/env/docs-index.sh` из рабочей папки организации, а не из
git. Файлы в `openspec/changes/<имя>/` получают вид `change` и доступны только
администратору, поэтому пользователю справка покажет спеку лишь после того, как она
окажется в `openspec/specs/user-guide/spec.md`. Поэтому спека синхронизируется в
основные спеки (`openspec-sync-specs`) до приёмки, а change архивируется после
неё, не раньше.

## Risks / Trade-offs

- [Тексты устареют при смене интерфейса] → каждый change, меняющий названия
  кнопок или пунктов меню, правит и `user-guide`; в задачи экранов это добавлено
  как проверка по названию (поиск по спеке).
- [Модель всё равно ответит технично] → ответ строится по найденным чанкам;
  если `user-guide` не поднимается, проверить ранжирование и открыть change в
  `wallet-docs`, не ослабляя требования.
- [Пользователь Android не увидит спеку] → зафиксировано в Non-Goals; follow-up в
  `android-wallet`.
- [Два места с названиями кнопок] → спека `user-guide` ссылается на дословные
  названия из спек экранов; при расхождении правда — в спеке экрана.
