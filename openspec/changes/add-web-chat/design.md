# Design

## Context

- SPA без сборки: `site/app.js` (IIFE, ES5). Экраны верхнего уровня
  (`renderReports`, `renderSettings`, `renderAdmin`, `renderLogin`…) целиком
  перезаписывают `#app.innerHTML`. Переходы внутри «Отчётов» — через
  `history.pushState`, без перезагрузки.
- На ширине до 700 px внизу закреплён `.mobile-tabbar` (`z-index: 30`), шторка
  «Ещё» — `z-index: 40`.
- Ближайший образец — «Трата своими словами» (`aiStartParse`/`aiPoll`):
  `POST /api/ai/jobs`, long-poll `?wait=25`, `DELETE` при отмене. Там ответ,
  пришедший после ухода с экрана, выбрасывается: попытка привязана к DOM.
- `refreshAiStatus()` вызывается при каждом открытии «Отчётов» (стартовый
  экран после входа) и уже учитывает `viewAsUser`.
- Контракт wallet-ai: `kind: chat`, `ChatInput`, `failure` чата, `AiSettings` —
  `wallet-ai/openapi.yaml` и `wallet-ai/openspec/specs/{ai-chat,ai-jobs,ai-providers}`.

## Goals / Non-Goals

**Goals:**
- Чат не зависит от того, какой экран в `#app`, и не ломается от его перерисовки.
- Ожидание ответа не привязано к видимости окна.
- Одно состояние, из которого рисуется окно и которое целиком сериализуется.

**Non-Goals:**
- Стриминг ответа, markdown в ответах.
- Несколько параллельных вопросов в одном диалоге.
- Синхронизация ленты между вкладками.

## Decisions

### D1. Свой корень `#chat-root` в `<body>`, не внутри `#app`
Корень создаётся из JS один раз (`document.body.appendChild`), рядом с `#app`.
Ни один `render*` его не трогает. Альтернатива — вставлять кнопку в каждый
экран — дала бы N мест разметки и потерю окна при каждой перерисовке.

### D2. Состояние — один объект `chat`, рисование — функция от него
`chat = {open, messages[], conversationId, pending{jobId, startedAt, key}|null,
lastAnswerAt, unread, draft}`. `renderChat()` перерисовывает окно из него
(лента — `escapeHtml` + `white-space: pre-wrap`). Любое изменение — через
`chatSave()` (в `sessionStorage`) и `renderChat()`. `draft` (текст в поле) не
сериализуется: перерисовка ленты не пересоздаёт поле ввода, поэтому фокус и
курсор не теряются.

### D3. Ожидание не зависит от окна
`chatPoll(seq, jobId)` сверяется только с порядковым номером попытки
`chatSeq` (растёт на «Новый диалог», «Выйти», смене пользователя), а не с
наличием DOM. Ответ записывается в `messages`, и если окно закрыто, ставится
`unread`. Предел 150 с, как у бота: при каждом ответе опроса
`Date.now() - pending.startedAt > 150000` → `DELETE` и сообщение о таймауте.
`startedAt` хранится в `sessionStorage`, поэтому предел действует и после F5.

### D4. `sessionStorage`, ключ `wallet.chat.v1`
Значение — `{user: email, conversationId, messages, pending, lastAnswerAt}`.
При загрузке запись чужого `user` удаляется. `messages` обрезаются до 50
последних. Альтернативы: `localStorage` пережил бы закрытие вкладки, хотя
wallet-ai помнит диалог только 30 минут, а на общем компьютере это хуже;
хранение на сервере требует нового API в wallet-ai без пользы для этой задачи.
Токенов в записи нет: веб их и не видит (httpOnly-cookie).

### D5. Доступность — из `refreshAiStatus`
Сейчас `refreshAiStatus` отфильтровывает `features` до
`parse_expense`/`statement_import`, и пункт «ИИ» видим при непустом списке.
`chat` вычисляется отдельно (`chatAvailable`) из исходного `features`, чтобы
пункт «ИИ» не появлялся только из-за чата. `viewAsUser` → `chatAvailable = false`.
`renderLogin()` прячет корень. Статус не перечитывается на других экранах:
до них можно дойти только через «Отчёты».

### D6. Модель — `GET /api/ai/settings` при первом открытии окна
Один запрос за загрузку страницы. Ошибка — строки нет. Подпись ответа берётся
из `result.provider` (`lmstudio` → «LM Studio», `claude` → «Claude», иначе
сам id), а не из настроек: модель могла смениться между вопросами.

### D7. `conversation_id` = `web-` + uuidV4
Укладывается в `[A-Za-z0-9_:-]{1,64}`. Ключ идемпотентности
`web-chat:` + uuidV4 создаётся один раз на нажатие и лежит в `pending.key`;
кнопка блокируется до ответа на `POST`, так что двойной клик второго задания
не создаёт.

### D8. Раскладка
Десктоп: кнопка 56 px, `right/bottom: 24px`; окно — `position: fixed`,
справа, `width: min(440px, 100vw)`, во всю высоту, `z-index: 50` (выше
шторки «Ещё»). Телефон (≤700 px): окно `inset: 0`; кнопка поднимается на
высоту таббара (`bottom: calc(72px + env(safe-area-inset-bottom))`), если он
есть на экране (`body.reports-open`), иначе `16px`. Подложки нет: окно на
десктопе не модальное, отчёты под ним остаются кликабельными.

Липкая панель `.st-footbar` «Импорта выписки» (`bottom: 0`) попадает в тот же
угол, что и кнопка; найдено на test-контуре в 4.2: кнопка закрывала «Записать»
на 1280, 1024 и 375 px. Кнопку не двигаем (высота панели меняется с выбором
строк), а пока она видна (`body.chat-available`), даём панели
`padding-right: 76px`.

### Правки в других сервисах
Не нужны. wallet-ai: `kind: chat`, `/api/ai/settings` и `features: chat` уже
в `main`. wallet-gateway: `/api/ai/*` уже проксируется. google-auth: обмен
токена для wallet-mcp делает сам wallet-ai.

## Risks / Trade-offs

- [Две вкладки с одним `sessionStorage` не делят] → у каждой свой диалог; это
  ожидаемо для `sessionStorage`.
- [wallet-ai перезапустился — история модели пропала, лента осталась] →
  модель переспросит; лента честно показывает то, что спрашивали.
- [Ответ модели может быть длинным] → лента прокручивается внутри окна,
  `overflow-wrap: anywhere`.
- [Чат-кнопка перекрывает контент в правом нижнем углу] → у «Отчётов» в этом
  углу нет управляющих элементов; на телефоне кнопка над таббаром.

## Migration Plan

Только статика: выкат образа wallet-web. Откат — предыдущий образ; запись
`wallet.chat.v1` в `sessionStorage` старой версией не читается и вреда не несёт.
