# Design

## Context

Зачем — в `proposal.md`. SPA — один `site/app.js` (ES5, IIFE) без сборки;
экран входа сейчас строится в одной функции и показывает ссылку на `/auth/google`.
Сессия — только httpOnly-cookie google-auth, JS её не видит. Все вызовы идут
относительными путями через wallet-gateway; `/auth/*` проходит без JWT-гейта.
Контракт новых ручек — `google-auth/openapi.yaml` (change `add-password-auth`),
здесь он не дублируется.

## Goals / Non-Goals

**Goals:**
- Вход, регистрация и установка пароля из браузера.
- Набор кнопок определяет сервер (`GET /auth/methods`), а не сборка SPA.

**Non-Goals:**
- Сброс пароля по почте и подтверждение email (отдельный change с SMTP).
- Показ статуса «email не подтверждён» в списке участников кошелька.
- Менеджер паролей, 2FA, капча.

## Decisions

### D1. Способы входа читаются с сервера при каждом показе экрана входа

SPA не хранит конфигурацию: `GET /auth/methods` запрашивается при показе экрана
входа (и приглашения). Так переключение `AUTH_METHODS` на сервере сразу видно
в браузере без выката статики. Недоступность методов — тот же экран ошибки, что и
недоступность `/auth/me` (одно поведение для «сервера нет»).

*Альтернатива:* зашить в сборку или кэшировать в `localStorage`. Отвергнуто:
рассинхрон с сервером и лишнее состояние.

### D2. Вход — fetch, а не отправка формы

`fetch POST /auth/login` с JSON и `credentials: 'include'`: сервер отвечает `200`
с профилем и cookie, SPA заново проходит проверку входа без перезагрузки.
Приглашение из `localStorage` при этом остаётся на месте и принимается обычным
путём. Форма `<form>` нужна ради менеджеров паролей (атрибуты `autocomplete`),
а отправка перехватывается (`preventDefault`).

### D3. Регистрация сразу выполняет вход

`POST /auth/register` всегда отвечает `202` и не открывает сессию (сервер не
раскрывает, занят ли email). Чтобы пользователь не вводил данные дважды, SPA после
`202` сама вызывает `POST /auth/login`. Если адрес занят, вход не пройдёт, и
пользователь получает нейтральное сообщение.

### D4. Предупреждение по `location.protocol`

SPA знает свою схему сама, предупреждение не зависит от ответа сервера и
показывается над обеими формами. Скрывать вход по HTTP SPA не должна: решение
остаётся за сервером (`ALLOW_INSECURE_AUTH`).

### D5. Секция «Пароль» только при включённом пароле

Ту же `GET /auth/methods` используют настройки. Для пользователей Google
секция даёт задать пароль без текущего; для остальных — сменить с текущим.

### D6. «Текущий пароль» показывается всегда

SPA не знает, есть ли у пользователя пароль: `GET /auth/me` этого не отдаёт, а
отдельной ручки нет. Поэтому поле «Текущий пароль» стоит в форме всегда, с
подписью «оставьте пустым, если пароля ещё нет», и `current_password`
отправляется только если оно заполнено. Сервер сам требует текущий пароль, если
он есть (`401` «неверный текущий пароль»). Так работают оба сценария (Google
задаёт пароль без текущего; пользователь с паролем меняет с текущим).

*Альтернатива:* добавить `has_password` в `GET /auth/me` и показывать поле по
нему. Точнее, но требует правки google-auth и отдельного rc; можно сделать позже,
не ломая клиента.

## Risks / Trade-offs

- **Пароль в памяти страницы** → только в поле формы до отправки, после ответа
  поля очищаются; токены в JS по-прежнему недоступны.
- **Лишний запрос `GET /auth/methods`** на каждый показ экрана входа → запрос
  лёгкий и без БД; экран входа показывается редко.
- **Ввод на `http://`** → предупреждение (D4); отказ приходит от сервера.
- **Тексты на русском, без локализации** — как остальной SPA.

## Migration Plan

Выкатывать после google-auth (`add-password-auth`) с включённым `AUTH_METHODS`
и после TLS (wallet-infra). Старая статика без `GET /auth/methods` продолжает
работать с Google. Откат — прежний образ wallet-web.

Правки в других сервисах не нужны: gateway проксирует `/auth/*` уже сейчас.
