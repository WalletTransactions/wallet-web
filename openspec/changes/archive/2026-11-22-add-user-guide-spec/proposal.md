# Proposal

## Why

Экран «Справка» отвечает по описанию системы, а оно написано для разработчиков:
на вопрос «Как добавить трату в приложении?» справка выдаёт
`POST /api/ai/jobs` и `kind: parse_expense`, а на «Как перевести деньги с карты в
наличные?» — «В описании системы этого нет.». Обычному пользователю веба справка
видна только по `wallet-web` и `wallet-web-eqdefault` вида `spec`, поэтому
пользовательские объяснения должны лежать именно здесь. Из-за этого же не снят
кадр «Вопрос по приложению» для страницы «Как это выглядит» (задача 6.4 change
`add-showcase-page` в wallet-site).

## What Changes

- Новая спека `user-guide` — пользовательские сценарии простым языком: один
  вопрос пользователя — одно требование, шаги названы так, как кнопки и пункты
  меню подписаны в интерфейсе.
- Охват: добавить трату или доход вручную; записать трату словами; перевести
  деньги между своими кошельками; загрузить выписку банка; посмотреть, куда уходят
  деньги; сравнить периоды; увидеть остатки по кошелькам; сменить валюту
  эквивалента; пригласить человека; спросить ассистента про свои траты; чем
  «Справка» отличается от «Спросить».
- Требование к языку ответов: без названий запросов, полей и идентификаторов.
- Поведение веба не меняется: код, e2e-тесты и экраны не трогаются.

## Capabilities

### New Capabilities
- `user-guide`: пользовательские сценарии работы с вебом и ответы справки на типовые вопросы обычного пользователя, простым языком и с названиями элементов интерфейса.

## Impact

- Только `wallet-web/openspec/specs/` (новая спека после архивации change). Код `site/`, `e2e/` и `README.md` не меняются: ни один экран не меняется.
- Чанки новой спеки попадают в индекс `wallet-docs` при очередной заливке индекса репозитория `wallet-web`; область `platform = web`, `telegram` и `mcp` их видит, `android` — нет (у неё только `android-wallet`).
- Правок `wallet-docs`, `wallet-gateway` и других сервисов не требуется.
