# Design

## Context

Сейчас в `site/app.js` две реализации одного экрана:

- вкладка «Иконки» в «Отчётах» — `refreshIcons()`: `fetchReport('icons')`
  (кэш `reportsCache`, `as_user_id` в режиме «Посмотреть как клиент»),
  разделы «Мои»/«Общие», только просмотр;
- админский экран — `renderAdminIcons()`/`renderAdminIconsScreen()` (кнопка
  «Иконки» под таблицей пользователей): «Общие» с формой и правкой
  (server-managed-icons, ещё не заархивирован) и «Иконки пользователя».

`GET /api/reports/icons` уже отдаёт у каждой иконки `uuid` (схема `Icon` в
`wallet-report/openapi.yaml`), поэтому правка общих иконок не требует
отдельного `GET /api/reports/admin/icons`. Картинка готовится в
`prepareIconImage()`: обрезка по центру до квадрата, 256×256, WEBP 0.9.

На Android круглая обрезка — `CircleCropView`: затемнение вне круга
(`0xB3201E1D`), `minScale` — картинка закрывает окно, `MAX_ZOOM = 8`,
`clampToWindow()` не даёт краю зайти в круг, результат — PNG с альфой 0 за
кругом. Веб повторяет это поведение, чтобы иконка с сайта и с телефона
выглядела одинаково.

## Goals / Non-Goals

**Goals:**
- Одна вкладка для просмотра и управления иконками; админский экран и его код
  удаляются целиком, а не прячутся.
- Редактор обрезки без библиотек (правило проекта: без CDN, только `site/vendor/`)
  и с одинаковым поведением мышью и пальцем.

**Non-Goals:**
- Добавление в «Свои» или в кошелёк другого пользователя (вариант «Куда
  добавить» один — «Общие»); серверных ручек для этого нет и в этом change не
  будет.
- Замена картинки у существующей иконки (по-прежнему: удалить и добавить).
- Поворот картинки и учёт EXIF-ориентации сверх того, что делает сам браузер
  (`image-orientation: from-image` по умолчанию в современных браузерах).

## Decisions

1. **Выпадающий `<select>` «Показать», а не вкладки.** Пользователь просил
   «выпадашку»; `<select>` нативно работает на телефоне и не спорит за ширину с
   формой добавления. Счётчики в подписях («Свои (N)») берутся из того же
   ответа `GET /api/reports/icons`. Выбор хранится в переменной модуля и
   переживает перезапрос (после правки сетка не прыгает на «Свои»).

2. **Права — по `currentUser.role === 'admin' && !viewAsUser`.** Тот же признак,
   что прячет кнопки записи в «Курсах валют» (currency-ui-tweaks, D5). Сервер
   всё равно проверяет роль в `/api/admin/icons*` — веб только не показывает
   то, что вернёт 403.

3. **«Общие» для правки — из `GET /api/reports/icons`, после записи — сброс
   ключа `icons` в `reportsCache` и `refreshIcons()`.** Альтернатива — держать
   отдельный `GET /api/reports/admin/icons` для «Общих» у админа: лишний запрос
   и второй источник одного и того же набора. Сброс по ключу — как у валют
   (`currencies?` в `reportsCache`).

4. **«Чужие» — ленивые запросы.** `GET /admin/users` уходит при первом выборе
   «Чужие» (не при каждом открытии «Отчётов»: обычному пользователю он вернёт
   403, а админу нужен редко). Иконки пользователя — `GET
   /api/reports/admin/icons?user_id=` мимо кэша, как сейчас.

5. **Редактор — один `<canvas>` + Pointer Events.**
   - Отрисовка: картинка с текущими `scale`/`offset`, поверх — затемнение
     `rgba(32,30,29,0.7)` с вырезанным кругом (`evenodd`), тонкая обводка круга.
   - Ввод: `pointerdown/move/up` с `setPointerCapture`; одна активная точка —
     сдвиг, две — щипок (масштаб вокруг середины между пальцами), `wheel` —
     масштаб вокруг курсора, `<input type="range">` «Масштаб» — вокруг центра
     круга. `touch-action: none` на canvas — страница не прокручивается и не
     масштабируется (сценарий «Масштаб на телефоне»).
   - Ограничения: `minScale = max(D/w, D/h)` (D — диаметр круга), `maxScale =
     8 × minScale`, после каждого жеста — `clamp` смещения, чтобы круг
     целиком лежал внутри картинки (порт `clampToWindow`).
   - Альтернатива — готовая библиотека (Cropper.js): +40 КБ в `site/vendor/` и
     прямоугольная модель с круглой маской через CSS; свои 150 строк проще
     сопровождать и повторяют Android один в один.

6. **Итог — отдельный canvas 256×256 с `clip()` по кругу.** Источник берётся
   в координатах исходного изображения (не с экранного canvas), поэтому
   качество не зависит от размера редактора на экране. За кругом — альфа 0.
   `toBlob('image/webp', 0.9)`; если вернулся PNG (Safari) — отправляется
   PNG, как и сейчас. Превью рядом с редактором — тот же результат, уменьшенный
   через `categoryIconHtml`-подобный круг, обновляется с троттлингом по
   `requestAnimationFrame`.

7. **Форма и редактор — разметкой во вкладке, без модального окна.** Модалки в
   проекте нет; на телефоне форма идёт в одну колонку: файл → редактор →
   название/тип/куда → «Добавить».

## Risks / Trade-offs

- [Порядок архивации: delta меняет требования, которые добавляет
  server-managed-icons] → архивировать после него; `openspec validate` это уже
  показывает (INFO «Archive would refuse this delta»).
- [Тест-задачи wallet-web#8 и #9 описывают старое расположение формы] → после
  выката обновить их раздел «Где находится» или закрыть до выката.
- [Фото 50 МП с телефона: декодирование в `Image` и отрисовка каждого кадра]
  → для редактора рисуется уменьшенная копия (длинная сторона ≤ 2048 px),
  итог 256×256 — из той же копии: при 8× круг всё равно покрывает ≥ 256 px
  исходника.
- [Прозрачные углы у WEBP/PNG] → и веб (`background-image` в круге), и Android
  (круглые view) показывают иконку кругом, углы не видны; на Android такой же
  формат даёт `IconCropActivity`.

## Migration Plan

1. Выкат как обычно: rc-тег wallet-web → test → ручная проверка (тест-задача
   на этот change) → финальный тег → prod.
2. Откат — предыдущий тег wallet-web (`env-rollback`): сервер не менялся,
   данные иконок совместимы в обе стороны.
