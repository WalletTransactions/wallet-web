# Design: пункт «ИИ» в вебе — трата своими словами

## Context

Шаг 5 `org/docs/TODO_wallet_ai.md`. wallet-ai уже даёт `GET /api/ai/status` и
задания `POST/GET/DELETE /api/ai/jobs` с `kind: parse_expense` (контракт —
`wallet-ai/openapi.yaml`); бот пользуется ими с 2026-10-11. Гейтвей проксирует
`/api/ai/*` в wallet-ai и `/sync/*` в wallet-api, принимая cookie `session`.
У пользовательского токена уже есть `aud: wallet-ai` и `scope: ai:use`
(`google-auth/src/token_claims.hpp`).

Что мешает: веб ещё ни разу не записывал операции. `POST /sync/push` по
браузерной сессии отвечает 403. Браузерный вход в google-auth не даёт
`device_id` (`google.cpp::browser_device`), а wallet-api без него отказывает
(`sync.cpp::authenticate_and_provision`), потому что ему не к чему привязать
`updated_by` и устройство.

Опирается на baseline: `reports-shell` (навигация, `PERIOD_FREE_VIEWS`,
`fetchReport`/`reportsCache`) и `web-session` (`apiFetch` с повтором через
`/auth/refresh`).

## Goals / Non-Goals

**Goals:**
- Трата текстом из веба с тем же инвариантом, что у бота: ИИ даёт черновик,
  запись делает пользователь.
- Запись через тот же `POST /sync/push`, что у телефона и бота, без второй
  write-стороны.
- Ручное заполнение той же карточки как запасной путь, когда ИИ не справился.

**Non-Goals:**
- Импорт выписки, конструктор шаблонов, чат (шаги 6–11 плана) — экран «ИИ»
  готов принять их следующими разделами, но сами разделы здесь не делаются.
- Доходы и переводы — только расход (`acc_fr` — кошелёк, `acc_to` — категория).
- Отдельный экран «Новая операция» вне «ИИ». Ручная карточка доступна только
  как запасной путь.
- Создание кошельков и категорий из веба.

## Decisions

### D1. У браузерной сессии появляется `device_id` (google-auth)
`browser_device` генерирует UUID v4 при каждом входе через Google. Он хранится в
refresh-сессии (Redis) вместе с `DeviceInfo`, а `issue_tokens` уже кладёт
непустой `device_id` в JWT. Старые сессии получают его лениво: в
`rotate_refresh_token` при `platform == "web"` и пустом `device_id` значение
генерируется перед `issue_tokens`. Свёртка сессий по `device_id`
(`auth.cpp:187`) веба не касается: каждый вход — новый UUID.

Отвергнуто:
- REST-ручка `POST /api/operations` в wallet-api без устройства. Это вторая
  реализация записи (`seq`, `change_stream`, проверки ссылок и ролей,
  идемпотентность), и `updated_by` остался бы пустым.
- Одно устройство «web» на пользователя. Тогда два браузера делили бы одно
  устройство, а `updated_by` не отличал бы их.

Следствие: в wallet-api копятся устройства `platform=web`, по одному на вход.
Это та же картина, что у переустановок приложения, и CHECK `device.platform` уже
допускает `web`.

### D2. Машинный код отказа (wallet-api)
Сейчас 403 без `device_id` отдаёт фразу. Меняем на `{"error": "device_required"}`,
чтобы веб отличал этот случай от `reader_cannot_write` и отвечал на него одним
повтором через `/auth/refresh`. Android всегда входит с `device_id` и этого
ответа не видит; бот тоже.

### D3. Экран «ИИ» — новая вкладка «Отчётов», а не отдельная страница
Добавляем `ai` в `REPORTS_NAV` (новая группа «ИИ»), `REPORTS_TITLES`,
`REPORTS_BUILT_VIEWS` и `PERIOD_FREE_VIEWS`, а также узел `view-ai` в разметку
`renderReports`. Пункт сначала скрыт и появляется после ответа
`GET /api/ai/status`. Статус запрашивается вне `refreshPeriod`, как
`refreshCurrencyPairs`. `parseReportsHash` для `ai` при скрытом пункте даёт
«Обзор». В `MOBILE_TABS` пункт не добавляется: на телефоне он в шторке «Ещё»,
четыре вкладки таббара не меняются.

### D4. Ожидание — long-poll, без SSE
Цикл `GET /api/ai/jobs/{id}?wait=25` (до 30 с таймаута гейтвея). Токен
отмены — счётчик попыток в модуле: ответ устаревшей попытки выбрасывается.
Уход с вкладки «ИИ» (`switchReportsView`) и «Отменить» вызывают `DELETE`.
Отдельной ручки для `beforeunload` нет: задание доживёт до TTL (10 мин) — так
принято в плане (§5, «Веб»).

### D5. Карточка — форма поверх списков из wallet-report
Списки кошельков и категорий берутся из `GET /api/reports/accounts` через
`fetchReport`: он кэшируется, а в режиме просмотра клиента пункт и так скрыт.
Системные категории (`system_kind` 1/2) и архивные счета отфильтрованы. Ответ
resolver только предвыбирает значения и упорядочивает кандидатов. Пользователь
может выбрать любое значение, поэтому `ask` и `reject` не тупик, а подсказка.
Валюта и `precision` берутся у выбранного кошелька.

### D6. Идентификаторы записи — при показе карточки
`batch_id` и `uuid` операции генерируются один раз, когда появляется карточка,
и живут, пока она открыта. Повтор после сетевой ошибки идёт с теми же
значениями, и wallet-api вернёт тот же `seq` (`sync_push_batch`). UUID v4 —
через `crypto.getRandomValues`: веб открывают по http в LAN, а там
`crypto.randomUUID` недоступен (не secure context).

### D7. После записи — `reportsCache = {}` и `refreshPeriod()`
Вкладки с периодом грузятся один раз (baseline, D4). Без перезагрузки новая
трата не появилась бы до смены фильтра. Запрос фоновый: пользователь остаётся
на «ИИ».

### D8. Кошелёк по умолчанию — `localStorage`
Последний кошелёк, с которого записали трату, сохраняется в `localStorage`
(`aiLastWalletUuid`, в `try/catch`) и уходит в `default_wallet_uuid`. У бота для
этого есть `/default`; в вебе отдельной настройки нет, и она не нужна, пока
трата вводится только здесь.

### Правки в других сервисах
- **google-auth:** D1 (`google.cpp::browser_device`, `auth.cpp::rotate_refresh_token`),
  юнит-тест на ленивую выдачу, README «Устройства».
- **wallet-api:** D2 (`sync.cpp`), `openapi.yaml` (`/sync/push` 403),
  интеграционный тест push с браузерным токеном.
- **wallet-ai, wallet-report, wallet-gateway:** без изменений.

## Risks / Trade-offs

- [Старая вкладка с токеном без `device_id`] → D2 и одиночный повтор через
  refresh; если refresh не помог — «Перезайдите…».
- [Пользователь — читатель леджера] → wallet-ai разберёт текст, а wallet-api
  откажет (`reader_cannot_write`). Скрывать пункт для читателя веб сейчас не
  может: роль известна только «Доступу». Принимаем лишний разбор, сообщение
  понятное.
- [Ручная карточка становится полноценной формой расхода] → рамка Non-Goals:
  она открывается только из экрана «ИИ», доходов и переводов нет.
- [Накопление устройств `web` в wallet-api] → видны в «Устройствах» как сессии;
  чистка — отдельная задача, если станет заметно.
- [GPU занят импортом в будущем] → `429 busy` уже обработан сообщением и
  ручной карточкой.

## Migration Plan

1. google-auth (D1) и wallet-api (D2) выкатываются первыми. Без веба они
   ничего не меняют для существующих клиентов.
2. Затем веб. Откат — выкат прошлого образа wallet-web; `device_id` в
   браузерных токенах остаётся безвредным.
