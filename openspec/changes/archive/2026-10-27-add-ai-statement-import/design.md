# Design: «Импорт выписки» в разделе «ИИ»

## Context

Сервер — `wallet-ai/openspec/changes/add-statement-import`: импорт как ресурс
`/api/ai/imports*` в базе `ai`. Разбор идёт в фоне, группы строк, правки через
`PATCH /rows`, готовые операции с детерминированными `uuid`, отметка
`/committed`. Запись делает клиент через `POST /sync/push`.

Веб после `add-ai-expense-text` уже умеет: экран «ИИ» (вкладка `ai` в
«Отчётах», без периода), `push` от браузерной сессии с `device_id` и
обработкой `device_required`, сброс `reportsCache` + `refreshPeriod()` после
записи. Этот change добавляет на тот же экран второй раздел.

## Goals / Non-Goals

**Goals:**
- Загрузить выписку и уйти: разбор не требует открытой вкладки.
- Проверить и поправить 50–200 строк быстро: фильтры по группам, массовые
  действия, правка прямо в строке, источник из документа под рукой.
- Записать всё одним действием без риска дублей.

**Non-Goals:**
- Уведомления вне веба (Telegram, push) — решено: только веб.
- Доходы и переводы (сервер их не предлагает).
- Создание категорий из экрана проверки.
- Редактирование уже записанных строк — после записи это обычные операции.

## Decisions

### D1. Маршрут проверки — подсостояние вкладки `ai`
Экран проверки — `#/reports/ai/import/<id>`, а не новая вкладка в
`REPORTS_BUILT_VIEWS`: в навигации он один пункт «ИИ». `parseReportsHash`
расширяется хвостом после `ai`, а «← К импортам» и браузерный «Назад» идут
через тот же стек истории `reportsHistory`. F5 на экране проверки открывает
его снова.

### D2. Опрос вместо long-poll
Импорт длится минуты, поэтому список опрашивается `GET /api/ai/imports` раз в
5 с, пока раздел открыт и есть незавершённые импорты. Вне раздела — раз в 30 с
ради метки на пункте «ИИ». Таймер останавливается, когда незавершённых
нет. Long-poll заданий здесь не нужен: клиент ничего не ждёт синхронно.

### D3. Метка «готово» — `localStorage`
Какие готовые импорты пользователь уже открыл, хранится в `localStorage`
(`aiSeenImports`, список id, в `try/catch`). Сервер о «просмотрено» не знает:
это удобство конкретного браузера, как свёрнутый сайдбар.

### D4. Файл — base64 в JSON
`FileReader.readAsDataURL` → `content_base64` без префикса. Ограничение 5 МБ
проверяется до чтения (`file.size`). Сервер принимает JSON, а не multipart
(wallet-ai D9), поэтому гейтвей ничего не разбирает.

### D5. Правка — автосохранение на `change`/`blur`
Каждое изменение поля сразу уходит `PATCH /rows` одной правкой, массовые
действия — одним `PATCH` с пачкой. Ответ — источник истины: веб перерисовывает
изменённые строки и чипы групп из ответа, а не из локального состояния.
Поэтому правило продавца, применённое сервером к соседним строкам, видно сразу.
Пока `PATCH` в полёте, строка помечена «сохраняю…». Следующая правка той же
строки ждёт ответа, чтобы ответы не пришли в обратном порядке.

### D6. Запись пачками по 50 из готовых операций сервера
Операции берутся из ответа `GET /imports/{id}` (там они уже собраны сервером),
а веб их не собирает. Перед записью веб перечитывает импорт, чтобы записать
актуальное. `batch_id` — UUID v4 на пачку (через `crypto.getRandomValues`, как
в `add-ai-expense-text`). Идемпотентность держится на `uuid` операций (`op_uuid`):
повтор пачки после сбоя, даже с новым `batch_id`, обновит те же операции, а не
создаст новые. После каждой пачки — `POST /committed`. Если оборвалось между
`push` и `/committed`, строки останутся незаписанными с точки зрения импорта,
и повтор просто перезапишет их тем же содержимым.

### D7. Таблица на десктопе, карточки на телефоне — одна разметка
Строка — `<div role="row">` с CSS grid. На ширине ≥700px — колонки, на
узкой — карточка. Отдельных двух шаблонов нет, переключение только в
`style.css`. Список не виртуализируется: до 1500 строк, а в фильтре по
умолчанию обычно меньше 200, DOM это выдерживает. При большем числе — порция
по 200 с кнопкой «Показать ещё».

### D8. Подтверждения — в разметке, без `window.confirm`
Удаление импорта и «Записать N» подтверждаются панелью внутри экрана. Причина —
baseline Р23 (`alert`/`confirm` блокируют автоматизацию браузера), и на
телефоне системный диалог выглядит чужеродно.

### Правки в других сервисах
- Нет. Все серверные зависимости — в `add-ai-expense-text` (google-auth,
  wallet-api) и `wallet-ai` `add-statement-import`.

## Risks / Trade-offs

- [Пользователь пропускает проверку и жмёт «Записать»] → по умолчанию в запись
  входит только группа «Готово к записи»: проблемные строки сами не попадают.
  Подтверждение показывает сумму итога, её легко сверить с выпиской.
- [Расхождение итога с выпиской из-за «не разобрано»] → в подтверждении, если
  группа не пуста: «Ещё N строк выписки не разобрано — посмотреть».
- [Две вкладки правят один импорт] → последний `PATCH` выигрывает. Ответ
  сервера перерисовывает строку, расхождение видно сразу. Блокировок не делаем.
- [Сессия истекла посреди долгой проверки] → `apiFetch` сам обновляет токен
  через `/auth/refresh`, а правки уже на сервере и не теряются.

## Migration Plan

Выкатывается после `wallet-ai` `add-statement-import`. Пока сервер не
объявил `statement_import`, раздел скрыт, так что порядок выката безопасен.
Откат — прошлый образ wallet-web.
