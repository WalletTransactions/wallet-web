# Proposal

## Why

Чат «Спросить» показывает «Думаю…», а ответ появляется целиком через 5–20 с.
wallet-ai и гейтвей отдают ход задания потоком (`GET /api/ai/jobs/{id}/events`,
changes `chat-sse-events` и `proxy-sse-stream`), бот уже показывает ответ по
мере генерации (`chat-live-reply` в wallet-telegram).

## What Changes

- Пока задание `chat` выполняется, веб читает его поток событий (`fetch` с
  `Accept: text/event-stream` и cookie-сессией, `EventSource` не подходит: ему не
  задать заголовки и нельзя продолжить с `Last-Event-ID`) и показывает текст в
  «пузыре» ответа по мере прихода.
- Событие `tool` сбрасывает черновик и ставит статус «Смотрю данные…»; пока
  текста нет, у «Думаю…» бегут точки.
- Итог по-прежнему из `GET /api/ai/jobs/{id}` (long-poll): подпись провайдера,
  сбои, предел 150 с, F5 во время ожидания не меняются.
- Нет потока (404, 429, нет `ReadableStream`, сеть, `AI_STREAM_ENABLED` выключен) —
  прежний long-poll. Поток, закрытый до `done` (таймаут гейтвея, обрыв),
  продолжается с `Last-Event-ID`, до трёх раз подряд, затем long-poll.

Вне объёма: Android (там нет чата), поток для `parse_expense`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities
- `ai-chat`: ответ показывается по мере генерации; без потока — как раньше.

## Impact

- Код: `site/app.js` (чат), одно правило в `site/style.css` (текст ответа не курсивом).
- Зависит от wallet-ai/гейтвея с потоком (выкачены на test, на prod нет); без них
  работает прежний long-poll.
- Проверка — в браузере на test (в wallet-web нет юнит-тестов).
