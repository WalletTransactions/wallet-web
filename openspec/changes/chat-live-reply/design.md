# Design

## Context

См. proposal.md. Чат — один объект `chat` в `site/app.js`, ожидание итога —
`chatPoll` (long-poll `?wait=25`), итог разбирается там же. Правок в других
сервисах нет: wallet-ai и гейтвей выкачены на test; `nginx.conf` веб-контейнера
к `/api` не причастен (всё идёт через гейтвей).

## Decisions

### D1. `fetch` + `ReadableStream`, не `EventSource`
`EventSource` не умеет заголовков и ручного `Last-Event-ID`, а нам нужен
`Accept` (гейтвей включает поток по нему) и своя логика переподключения. Читаем
`res.body.getReader()`, разбираем SSE-кадры сами (≈30 строк). Cookie сессии
уходит как у остальных запросов (`credentials: 'include'`, `apiFetch` с
обновлением по 401).

### D2. Итог — из `GET /api/ai/jobs/{id}`
Поток нужен только для показа черновика. После `done`/`error` (или любого
неожиданного конца потока) вызывается прежний `chatPoll`: он же разбирает
`done`, сбои, подпись и предел 150 с. Так не дублируется ни одна ветка сбоев.

### D3. Обновление «пузыря» без перерисовки ленты
Событий десятки в секунду. На `delta` меняется `textContent` одного элемента
`.chat-pending`, лента целиком не перерисовывается (`chatRender` — только при
смене состояния). Прокрутка вниз — если пользователь уже внизу.

### D4. Переподключение и запасной путь
Поток закрылся без `done`/`error` (таймаут чтения гейтвея 30 с при молчании,
обрыв): открыть заново с `Last-Event-ID` последнего события, не больше 3 раз
подряд без новых событий. 404/429, не-200, нет `ReadableStream` или сетевая
ошибка — сразу `chatPoll`. 401 — как у long-poll: вход, после F5 ожидание
продолжится (черновик не сохраняется, на F5 начнётся поток с начала журнала).

### D5. Точки
Пока текста нет, таймер раз в 700 мс меняет «Думаю.», «Думаю..», «Думаю…»
(и «Смотрю данные…»); останавливается при первом тексте, итоге и «Новом диалоге».

## Risks / Trade-offs

- [Нет юнит-тестов у веба] → проверка в браузере на test: поток, 404-запасной путь, обрыв.
- [Длинный ответ перерисовывается часто] → меняется один текстовый узел.
- [Поток открыт, пока вкладка в фоне] → браузер может приостановить; итог всё равно придёт long-poll'ом.

## Migration Plan

Выкатить веб; без потока на сервере работает прежний long-poll. Откат — предыдущий тег.
